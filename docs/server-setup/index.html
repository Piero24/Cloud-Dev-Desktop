Server-Side Setup

For any Linux server with Docker and Docker Compose installed. No CasaOS required.

Step 1: Create directories​

mkdir -p cloud-dev-stack/{config,projects,vscode-config,init.d}
cd cloud-dev-stack

Step 2: Download the files​

# Container init script
curl -fsSL https://raw.githubusercontent.com/Piero24/Cloud-Dev-Desktop/main/init.sh \
  -o init.d/99-ssh.sh
chmod +x init.d/99-ssh.sh

# Plain Docker Compose file (no CasaOS metadata)
curl -fsSL https://raw.githubusercontent.com/Piero24/Cloud-Dev-Desktop/main/compose.yaml \
  -o compose.yaml

Step 3: Edit the values​

nano compose.yaml

Replace:

  • CHANGE_ME_USERNAME — system username inside the container (default: abc). Used for SSH and file ownership
  • CHANGE_ME_WEB_PASSWORD — login password for both KasmVNC (desktop) and code-server
  • CHANGE_ME_SUDO_PASSWORD — sudo password inside the container, also used for SSH login
  • CUSTOM_RES_W / CUSTOM_RES_H — desktop resolution in pixels (default 1920x1080). Lower = bigger text/icons
  • TZ — set to your timezone
  • npm-network — verify this matches your NPM Docker network name (docker network ls to check)

Step 4: Create the NPM network​

If you already have Nginx Proxy Manager running with a custom network, skip this. Otherwise create the network first:

docker network create npm-network

Step 5: Start the stack​

docker compose up -d
docker ps | grep dev-

You should see two containers: dev-desktop and dev-vscode.

Step 6: Test direct access (before NPM)​

These test the containers directly — no proxy yet:

TestURL / Command
Web desktophttp://<server-ip>:3000 — KasmVNC login (user: your CUSTOM_USER, pass: CHANGE_ME_WEB_PASSWORD)
Web VS Codehttp://<server-ip>:9090 — code-server login (pass: CHANGE_ME_WEB_PASSWORD)
SSHssh -p 3434 <CUSTOM_USER>@<server-ip> — login with SUDO_PASSWORD

If all three work, the stack is running correctly. The rest is wiring it up for daily use.

Post-Setup​

These steps are not required for the stack to run — they wire up external access, the API key, and monitoring.

Replace the DeepSeek API key​

After the container starts for the first time, edit the persisted zshrc:

nano config/.zshrc
# Find: ANTHROPIC_AUTH_TOKEN=<your DeepSeek API Key>
# Replace with your actual key

Or from inside the container:

docker exec -it dev-desktop bash
nano ~/.zshrc

Wire up Nginx Proxy Manager​

In your existing NPM dashboard (port 81), add two Proxy Hosts:

DomainForward HostnameForward PortWebSocketSSL
desktop.yourdomain.comdev-desktop3000ONLet's Encrypt
code.yourdomain.comdev-vscode8443ONLet's Encrypt
WebSocket support is mandatory

Both KasmVNC (desktop) and code-server rely on WebSocket connections. Without the WebSocket Support toggle enabled in NPM, you'll see:

  • Desktop: login page loads, then "WebSocket disconnected. Attempting to reconnect..." loops forever
  • Code-server: connection resets or "This application requires a secure connection" errors

No Advanced tab config needed — just SSL + WebSocket. Each app has its own password (the CHANGE_ME_WEB_PASSWORD you set in Step 3).

tip

dev-desktop and dev-vscode are Docker container names. Because they share npm-network with NPM, Docker's internal DNS resolves these names automatically.

Beszel agent (optional)​

Sends CPU, RAM, disk, and Docker metrics to your existing Beszel hub.

Get the agent key: In your Beszel hub UI, click Add system and copy the SSH public key. Paste it as CHANGE_ME_BESZEL_KEY in the compose file.

Verify the listen port: The agent listens on port 45002 (LISTEN env var). Make sure your Beszel hub is configured to connect to this server on port 45002.
