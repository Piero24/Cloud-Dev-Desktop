# Daily Workflow

## Starting a session

```bash
# Open terminal, establish the persistent SSH tunnel
ssh clouddev
# → Enter SUDO_PASSWORD
# → You're connected. You can close this terminal or leave it open.
```

## Persistent sessions with tmux

The server auto-detects where you're connecting from and starts tmux only when needed.

**Setup (one-time):** In Termius, edit your clouddev host → add environment variables:

| Key | Value | Purpose |
|-----|-------|---------|
| `TMUX_AUTO` | `1` | Auto-attach tmux on connect |
| `TMUX_TIMEOUT` | `2` | Kill detached session after N hours (`-1`=never, `0`=on detach) |

With `TMUX_TIMEOUT=2`: if you disconnect and don't reconnect within 2 hours, the tmux session auto-cleans. No zombie sessions.

**From Mac/PC:** connects normally — no tmux, close terminal = everything stops.

```bash
ssh clouddev          # normal shell
```

**From iPhone/Termius:** auto-attaches to a persistent tmux session — switch apps, lose signal, everything keeps running.

```bash
ssh clouddev          # → auto-attached to tmux "main" (Termius sent TMUX_AUTO=1)
claude                # runs inside tmux — survives disconnects
```

Next time you connect from Termius, you're back in the same session.

**How it works:** Termius sends `TMUX_AUTO=1` via SSH. The server's `.bashrc` checks for it: if set → `exec tmux`, if not → normal shell. No typing, no flags, completely automatic.

**Key commands inside tmux:**

| Action | Command |
|--------|---------|
| Detach (leave running) | `Ctrl+B` then `D` |
| Scroll up | `Ctrl+B` then `[` (arrows, `q` to quit) |
| New session | `tmux new -A -s name` |
| List sessions | `tmux ls` |
| Manual attach anytime | `ta` (alias for `tmux new -A -s main`) |
| Kill current session | `tmux kill-session` |
| Kill all sessions | `tmux kill-server` |
| Kill all except current | `tmux kill-session -a` |
| **Keep session forever** | `tmux-keep` — prevents auto-cleanup for this session |

:::tip Override the timeout

Mid-task and realize you need more time? Run `tmux-keep` inside the tmux session. The cleanup daemon will skip it — it stays alive until you manually kill it, regardless of `TMUX_TIMEOUT`.

:::

## Working server-side (no Mac needed)

You don't need a Mac. Everything runs on the server:

- **VS Code**: browser at `https://code.yourdomain.com`
- **Terminal**: SSH from anywhere, or use the terminal in the web desktop
- **Claude Code / long tasks**: inside tmux — survives disconnects
- **Files**: live at `/projects/` — visible in all apps

## Working Mac-side (optional)

If you prefer editing files locally on your Mac with automatic sync to the server:

1. Open VS Code → open your workspace file
2. Edit files normally
3. When you switch away from a file, VS Code autosaves → Run on Save fires `rsync --delete` → changed files upload through the SSH tunnel
4. If you delete a file locally, rsync removes it from the server too
5. The server is now an exact mirror of your local folder

This requires the SSH ControlMaster setup from [Mac-Side Setup](./mac-setup).

## Accessing from elsewhere

| Method | URL / Command | Auth |
|--------|---------------|------|
| Ubuntu Desktop (browser) | `https://desktop.yourdomain.com` | Password |
| VS Code (browser) | `https://code.yourdomain.com` | Password |
| SSH from anywhere | `ssh clouddev` (port 3434) | Password |
| SSH from iPhone (Termius) | Add host with port 3434 | Password |

## Ending a session

To close the SSH tunnel (ControlMaster):

```bash
ssh -O exit clouddev
```

:::note

The tunnel auto-closes after 16 hours of inactivity. If the server reboots, the tunnel dies — run `ssh clouddev` again.

tmux sessions survive disconnects but not server reboots. Reattach with `tmux attach -t main` after reboot.

:::
