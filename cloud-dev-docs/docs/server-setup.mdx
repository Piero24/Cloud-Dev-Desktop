# Server-Side Setup (CasaOS)

## Step 1: Create directories on the CasaOS host

```bash
mkdir -p /DATA/AppData/cloud-dev/{config,projects,vscode-config,init.d,authelia-config,landing,notifications}
```

## Step 2: Create the init script

This script runs on every container boot. It installs SSH, system packages, nvm + Node LTS, Claude Code, and forces all package managers to install into `/config` (persistent).

Create the file `/DATA/AppData/cloud-dev/init.d/99-ssh.sh`:

```bash
#!/bin/bash
# ================================================================
# Cloud Dev Stack — Container init script
# Runs on every container boot (linuxserver cont-init.d hook)
# Installs system packages + SSH + nvm + Node + Claude Code
# Forces all package managers to install into /config (persistent)
# ================================================================

# ---- Helper: add line to file if not already present ----
add_line() {
    local line="$1" file="$2"
    if [ -f "$file" ] && grep -qF "$line" "$file" 2>/dev/null; then
        return 0
    fi
    echo "$line" >> "$file"
}

# ---- System packages (reinstalled every boot — fast) ----
echo "[cloud-dev] Installing system packages..."
apt-get update -qq
apt-get install -y -qq \
    openssh-server \
    build-essential \
    python3-pip \
    python3-venv \
    git \
    curl \
    docker.io \
    zsh

# ---- SSH server ----
echo "[cloud-dev] Configuring SSH..."
sed -i 's/#PasswordAuthentication.*/PasswordAuthentication yes/' /etc/ssh/sshd_config
sed -i 's/^PasswordAuthentication no/PasswordAuthentication yes/' /etc/ssh/sshd_config
echo "abc:${SUDO_PASSWORD}" | chpasswd
service ssh start
echo "[cloud-dev] SSH server started."

# ---- nvm + Node LTS (persists to /config/.nvm) ----
if [ ! -d /config/.nvm ]; then
    echo "[cloud-dev] Installing nvm + Node LTS..."
    su - abc -c 'curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.40.1/install.sh | bash'
    su - abc -c 'export NVM_DIR="$HOME/.nvm" && [ -s "$NVM_DIR/nvm.sh" ] && . "$NVM_DIR/nvm.sh" && nvm install --lts'
else
    echo "[cloud-dev] nvm already installed, skipping."
fi

# ---- npm global prefix → /config ----
if [ -d /config/.nvm ]; then
    su - abc -c 'mkdir -p ~/.npm-global'
    if [ ! -f /config/.npmrc ] || ! grep -q "prefix" /config/.npmrc 2>/dev/null; then
        echo 'prefix=~/.npm-global' >> /config/.npmrc
    fi
fi

# ---- Claude Code ----
if [ -d /config/.nvm ]; then
    if ! su - abc -c 'export NVM_DIR="$HOME/.nvm" && [ -s "$NVM_DIR/nvm.sh" ] && . "$NVM_DIR/nvm.sh" && which claude 2>/dev/null'; then
        echo "[cloud-dev] Installing Claude Code..."
        su - abc -c 'export NVM_DIR="$HOME/.nvm" && [ -s "$NVM_DIR/nvm.sh" ] && . "$NVM_DIR/nvm.sh" && npm install -g @anthropic-ai/claude-code'
    else
        echo "[cloud-dev] Claude Code already installed, skipping."
    fi
fi

# ---- Shell config: force pip/npm/Go to install into /config ----
for rcfile in /config/.bashrc /config/.zshrc; do
    add_line 'export PIP_USER=yes' "$rcfile"
    add_line 'export PIP_BREAK_SYSTEM_PACKAGES=1' "$rcfile"
    add_line 'export GOPATH=~/go' "$rcfile"
    add_line 'export PATH=~/go/bin:~/.npm-global/bin:$PATH' "$rcfile"
    add_line 'export NVM_DIR="$HOME/.nvm"' "$rcfile"
    add_line '[ -s "$NVM_DIR/nvm.sh" ] && \. "$NVM_DIR/nvm.sh"' "$rcfile"
done

# ---- DeepSeek API env vars (for Claude Code) ----
if ! grep -q "ANTHROPIC_BASE_URL" /config/.zshrc 2>/dev/null; then
    cat >> /config/.zshrc << 'DEEPSEEK'
# Claude Code via DeepSeek API
export ANTHROPIC_BASE_URL=https://api.deepseek.com/anthropic
export ANTHROPIC_AUTH_TOKEN=<your DeepSeek API Key>
export ANTHROPIC_MODEL=deepseek-v4-pro[1m]
export ANTHROPIC_DEFAULT_OPUS_MODEL=deepseek-v4-pro[1m]
export ANTHROPIC_DEFAULT_SONNET_MODEL=deepseek-v4-pro[1m]
export ANTHROPIC_DEFAULT_HAIKU_MODEL=deepseek-v4-flash
export CLAUDE_CODE_SUBAGENT_MODEL=deepseek-v4-flash
export CLAUDE_CODE_EFFORT_LEVEL=max
DEEPSEEK
fi

# ---- Fix ownership ----
chown -R abc:abc /config

echo "[cloud-dev] Init complete. SSH is running. nvm, Node, Claude Code are ready."
```

Make it executable:

```bash
chmod +x /DATA/AppData/cloud-dev/init.d/99-ssh.sh
```

**Replace these values before submitting:**

- `CHANGE_ME_AUTHELIA_PASSWORD` — your Authelia account password (used for Authelia login + app logins)
- `CHANGE_ME_SUDO_PASSWORD` — sudo password inside the container (also used for SSH)

- `TZ` — set to your timezone

## Step 7: Wire up Nginx Proxy Manager

In your existing NPM dashboard (port 81), add three Proxy Hosts.

### 7a. Create the proxy hosts

| Domain | Forward Hostname | Forward Port | WebSocket | SSL |
|--------|-----------------|--------------|-----------|-----|
| `general.yourdomain.com` | `dev-landing` | `80` | — | Let's Encrypt |
| `desktop.yourdomain.com` | `dev-desktop` | `3000` | **ON** | Let's Encrypt |
| `code.yourdomain.com` | `dev-vscode` | `8443` | **ON** | Let's Encrypt |

:::warning WebSocket support is mandatory
Both KasmVNC (desktop) and code-server rely on WebSocket connections. Without the **WebSocket Support** toggle enabled in NPM, you'll see:
- Desktop: login page loads, then "WebSocket disconnected. Attempting to reconnect..." loops forever
- Code-server: connection resets or "This application requires a secure connection" errors
:::

### 7b. Add Authelia forward-auth to each proxy host

In the **Advanced** tab of each proxy host, paste this:

```nginx
# Authelia forward-auth — redirects to login if not authenticated
auth_request /authelia;
error_page 401 =302 https://general.yourdomain.com/?rd=$scheme://$http_host$request_uri;

location /authelia {
    internal;
    proxy_pass http://dev-auth:9091/api/authz/forward-auth;
    proxy_set_header Host $http_host;
    proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-URI $request_uri;
    proxy_set_header X-Forwarded-Method $request_method;
}
```

Do this for all three domains (`general`, `desktop`, `code`).

**How it works:**
- Every request first hits Authelia's `/api/authz/forward-auth`
- If authenticated (valid session cookie) → request passes through to the backend
- If NOT authenticated → Authelia returns 401 → user is redirected to `general.yourdomain.com` where Authelia shows the login page
- After login + TOTP, user is redirected back to where they wanted to go

:::tip
`dev-desktop`, `dev-vscode`, `dev-auth`, and `dev-landing` are Docker container names. Because they share `npm-network` with NPM, Docker's internal DNS resolves these names automatically.
:::

## Step 8: Configure Authelia

Create the Authelia configuration files in `/DATA/AppData/cloud-dev/authelia-config/`.

### 8a. `configuration.yml`

```yaml
---
theme: dark

default_redirection_url: https://general.yourdomain.com

server:
  host: 0.0.0.0
  port: 9091

log:
  level: info

totp:
  issuer: CloudDev
  period: 30
  skew: 1

authentication_backend:
  file:
    path: /config/users.yml
    password:
      algorithm: argon2id
      iterations: 1
      salt_length: 16
      parallelism: 8
      memory: 64

access_control:
  default_policy: deny
  rules:
    - domain:
        - "general.yourdomain.com"
        - "desktop.yourdomain.com"
        - "code.yourdomain.com"
      policy: two_factor

session:
  name: clouddev_session
  domain: yourdomain.com
  secret: CHANGE_ME_SESSION_SECRET
  expiration: 16h
  inactivity: 2h

regulation:
  max_retries: 5
  find_time: 2m
  ban_time: 10m

storage:
  local:
    path: /config/db.sqlite3

notifier:
  filesystem:
    filename: /config/notifications/auth.log
```

:::warning Session domain
`session.domain` must be `yourdomain.com` (no subdomain, no leading dot) so the session cookie works across `general.yourdomain.com`, `desktop.yourdomain.com`, and `code.yourdomain.com`.
:::

:::tip Session secret
Generate a strong random secret:
```bash
openssl rand -base64 64 | tr -d '\n'
```
Replace `CHANGE_ME_SESSION_SECRET` with the output.
:::

### 8b. `users.yml`

```yaml
users:
  your-username:
    disabled: false
    displayname: "Your Name"
    password: CHANGE_ME_PASSWORD_HASH
    email: you@example.com
    totp:
      secret: CHANGE_ME_TOTP_SECRET
```

**How to generate values:**

1. **Password hash** — run this, enter your password when prompted:
   ```bash
   docker run --rm authelia/authelia:latest authelia crypto hash generate argon2
   ```
   Copy the output (starts with `$argon2id$...`) into the `password` field.

2. **TOTP secret** — generate a base32 secret:
   ```bash
   openssl rand -base64 32 | tr -d '=' | tr '+/' 'AB'
   ```
   This is the same secret you'll add to your authenticator app (Step 10).

## Step 10: Enroll TOTP (authenticator app)

You'll use the **same TOTP secret** for both web (Authelia) and SSH login. One authenticator app entry unlocks everything.

### 10a. Add to your authenticator app

Create a QR code from the secret you put in `users.yml`:

```bash
TOTP_SECRET="<your-base32-secret>"
ISSUER="CloudDev"
ACCOUNT="your-username"
```

Then generate a QR code URI:

```
otpauth://totp/CloudDev:your-username?secret=<secret>&issuer=CloudDev&algorithm=SHA1&digits=6&period=30
```

You can render this URI as a QR code using any online tool, or add it manually to your authenticator app (Aegis, Authy, Bitwarden, 2FAS, Raivo, etc.).

### 10b. Test web login

1. Visit `https://general.yourdomain.com`
2. You should see the Authelia login page
3. Enter your username and password
4. Authelia prompts for a TOTP code
5. Enter the 6-digit code from your authenticator app
6. You're redirected to the landing page
7. Click Desktop or Code — no re-auth needed

### 10c. Set up SSH TOTP (same secret)

SSH uses the **same TOTP secret**. Skip this now — you'll configure it after the containers are running. See the [SSH TOTP section in Tips & Troubleshooting](./tips#ssh-totp-same-code-as-web).

## Step 11: Login webhook notifications (optional)

Authelia writes authentication events to `/config/notifications/auth.log` (as configured in Step 8a). To forward these to a webhook (Discord, Slack, custom URL):

### 11a. Create the webhook script

Create `/DATA/AppData/cloud-dev/notifications/webhook.sh`:

```bash
#!/bin/bash
# Tail Authelia auth log and fire webhook on successful logins
# Run inside dev-desktop: docker exec -d dev-desktop /config/notifications/webhook.sh

WEBHOOK_URL="CHANGE_ME_WEBHOOK_URL"
LOG_FILE="/config/notifications/auth.log"
LAST_POS=0

while true; do
  if [ -f "$LOG_FILE" ]; then
    SIZE=$(stat -c%s "$LOG_FILE" 2>/dev/null || stat -f%z "$LOG_FILE" 2>/dev/null)
    if [ "$SIZE" -gt "$LAST_POS" ]; then
      NEW_LINES=$(tail -c +$((LAST_POS + 1)) "$LOG_FILE" | grep -i "successfully authenticated")
      if [ -n "$NEW_LINES" ]; then
        while IFS= read -r line; do
          curl -s -X POST "$WEBHOOK_URL" \
            -H "Content-Type: application/json" \
            -d "{\"text\":\"🔐 Login: $line\"}" > /dev/null 2>&1
        done <<< "$NEW_LINES"
      fi
    fi
    LAST_POS=$SIZE
  fi
  sleep 5
done
```

Make it executable:
```bash
chmod +x /DATA/AppData/cloud-dev/notifications/webhook.sh
```

Replace `CHANGE_ME_WEBHOOK_URL` with your actual webhook URL.

### 11b. Start the webhook watcher

After deploying all containers, run this from the CasaOS host:

```bash
docker exec -d dev-desktop /config/notifications/webhook.sh
```

This runs in the background inside `dev-desktop` and fires your webhook whenever someone logs in successfully.

To make it survive container restarts, add it to the init script (`99-ssh.sh`):

```bash
# In 99-ssh.sh, add after the "service ssh start" line:
if [ -f /config/notifications/webhook.sh ]; then
    nohup /config/notifications/webhook.sh > /dev/null 2>&1 &
    echo "[cloud-dev] Webhook watcher started."
fi
```
