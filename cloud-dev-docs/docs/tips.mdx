# Tips & Troubleshooting

## Dev server port forwarding

If you run a dev server inside the container (e.g., `npm run dev` on port 5173), forward it to your Mac:

```bash
ssh -L 5173:localhost:5173 clouddev
```

Then open `http://localhost:5173` in your Mac's browser. Repeat for each port you need. The forwarded port stays alive as long as the SSH tunnel is open.

## Keeping Claude Code up to date

Claude Code updates frequently. To update inside the container:

```bash
docker exec -it dev-desktop bash
su - abc
source ~/.nvm/nvm.sh
npm update -g @anthropic-ai/claude-code
```

The update persists in `/config/.npm-global` — no need to redo it after rebuilds.

## SSH TOTP (same code as web)

SSH uses the **same TOTP secret** as web login. One authenticator app code works everywhere.

**What is PAM?** PAM (Pluggable Authentication Modules) is the Linux system that handles login authentication. `libpam-google-authenticator` is a PAM module that adds TOTP to SSH. Despite the "Google" in the name, it works with **any** authenticator app (Aegis, Authy, Bitwarden, 2FAS, Raivo, etc.) — Google just wrote the PAM module.

### Setup

Run these commands **inside the dev-desktop container**:

```bash
# Exec into the container
docker exec -it dev-desktop bash

# Install the PAM TOTP module (reinstalled each boot — add to init script for permanence)
sudo apt-get install -y libpam-google-authenticator

# Edit /etc/pam.d/sshd — add this line:
echo "auth required pam_google_authenticator.so" >> /etc/pam.d/sshd

# Enable keyboard-interactive auth in SSH
sed -i 's/^ChallengeResponseAuthentication.*/ChallengeResponseAuthentication yes/' /etc/ssh/sshd_config
```

### Configure your TOTP secret

As the `abc` user, use the **same base32 secret** from your Authelia `users.yml`:

```bash
su - abc
```

Instead of running `google-authenticator` (which generates a new secret), manually create `~/.google_authenticator`:

```bash
cat > ~/.google_authenticator << 'EOF'
YOUR_TOTP_SECRET_BASE32
" RATE_LIMIT 3 30 1715091060
" WINDOW_SIZE 17
" DISALLOW_REUSE
" TOTP_AUTH
EOF
```

Replace `YOUR_TOTP_SECRET_BASE32` with the same secret from `users.yml`.

Set correct permissions:
```bash
chmod 400 ~/.google_authenticator
```

Then restart SSH:
```bash
sudo service ssh restart
```

### Make it survive container rebuilds

Add to `/DATA/AppData/cloud-dev/init.d/99-ssh.sh`, after the `service ssh start` line:

```bash
# ---- SSH TOTP (PAM) ----
if ! grep -q "pam_google_authenticator.so" /etc/pam.d/sshd 2>/dev/null; then
    apt-get install -y -qq libpam-google-authenticator
    echo "auth required pam_google_authenticator.so" >> /etc/pam.d/sshd
    sed -i 's/^ChallengeResponseAuthentication.*/ChallengeResponseAuthentication yes/' /etc/ssh/sshd_config
fi
```

The `~/.google_authenticator` file lives in `/config/.google_authenticator` (persistent), so your TOTP secret survives rebuilds automatically.

### Login flow

```
$ ssh clouddev
Password: <SUDO_PASSWORD>
Verification code: <6-digit TOTP from authenticator app>
$   # logged in
```

The same 6-digit code shown in your authenticator app works for both:
- Web login (Authelia)
- SSH login (PAM)

### Adding to your init script (permanent)

The PAM module install is ephemeral (apt packages don't persist). Add this to your init script to install it on every boot.

## Docker-in-Docker permissions

The `docker.sock` mount gives the container root access to the host's Docker daemon. The `abc` user inside the container may need to be in the `docker` group to use it without `sudo`. If you get permission errors:

```bash
docker exec -it dev-desktop bash
sudo usermod -aG docker abc
# Then restart the container
```

You may also need to match the host's docker GID inside the container.

## Multiple projects

The rsync `cmd` hardcodes the project path. For multiple projects, create separate `.code-workspace` files — one per project. Each contains its own `emeraldwalk.runonsave` command with the correct server path.

## Known edge cases

### rsync timing

If you edit a file and immediately run a command on the server that reads it, the server might still have the old version if you haven't clicked away yet. Click away from the editor first, or hit `Cmd+S` to force a save (Run on Save still fires on manual save).

### First connection of the day needs a terminal

You must run `ssh clouddev` from a terminal to establish the tunnel. VS Code's Run on Save will fail if the tunnel isn't open.
